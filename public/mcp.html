How MCP auth works now — OAuth 2.1 via Supabase Auth (the 2026-08 connector-auth conversion)

Every MCP server authenticates callers with OAuth 2.1 through Supabase Auth. The authorization server is gfsdpwiqzshhexkofiif.supabase.co/auth/v1, consent is granted at /oauth/consent with your normal gateway login, and each server enforces its own MCP_ALLOWED_EMAILS allowlist (fail closed — an address that isn't listed is refused).
Two different reconnects — don't mix them up.
1. A Claude connector lost access (tools vanished, or Claude says the connector needs authorization): remove and re-add the connector in claude.ai → Settings → Connectors, then approve at the consent page with your gateway login. This is client-initiated — there is nothing to click here.
2. A server lost its provider tokens (QuickBooks / Zoho / Service Fusion expired or were revoked): use Provider Connections below. That re-runs the provider OAuth dance; it has nothing to do with Claude's access to the server.
