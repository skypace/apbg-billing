🔗 Connections & Reconnect — the reconnect desk for Service Fusion & QuickBooks logins

When a Service Fusion or QuickBooks connection dies, apps stop syncing (SF expenses stop landing, QBO bills stop posting). We run several separate SF and QuickBooks logins — one per app — so a hiccup in one never takes down the others. The trouble is they look identical from the outside, and reconnecting the wrong one wastes an afternoon. Each row below is one login: a health light (🟢 healthy · 🟡 needs a look · 🔴 down · ⚪ lives in another site, not watched here), the id so you know exactly which one it is, and a Reconnect button that opens the correct sign-in for that one. Everything green = nothing to do. Only click Reconnect on a row that's red or yellow.

🔍 Service Fusion Changes report — comms-settings changes, new / removed customers, renames

Re-scans every SF customer, diffs against the last snapshot, and emails the report (communication-settings changes per customer, new customers, removed customers — SF's API can't distinguish deleted from deactivated — and renames). SF's API is read-only for customers, so fixes happen in the SF web UI.

🧾 SF Expenses → QuickBooks — post each Service Fusion job expense as a QBO bill to its "Purchased From" vendor

Takes the Service Fusion expense drafts that haven't been billed and creates a QuickBooks bill for each against the vendor on record (SF Purchased From) — emailing a confirmation per bill. Expenses with a blank vendor, or a vendor that isn't in QuickBooks, are held and email a needs-attention alert instead. Preview is a dry run (nothing posts) and emails a summary; Post now creates the bills.
